**Q:** My laptop battery drains fast because Nimbus checks for changes too often. What can I change?

*Note in test-questions.json:* poll_interval in nimbus.toml; never says 'poll'.

> Raise the `poll_interval` setting in your `nimbus.toml`. It controls how often Nimbus asks the server for remote changes, and lower values make changes appear sooner but use more battery and bandwidth. [1] The default is 30 seconds [1], so choose a larger number (in seconds) to reduce how often it checks.
>
> - **Where to edit:** Nimbus looks for a `nimbus.toml` in the current folder first and falls back to the one in your home folder. [1]
> - **Applying the change:** Changes take effect the next time Nimbus starts. If it's running as a background service, restart it with `nimbus service restart`. [2]
> - **Testing first:** You can override a setting for a single run with an environment variable such as NIMBUS_POLL_INTERVAL, which takes priority over the file. [2]
> - **Need changes right away:** You can run `nimbus sync` manually when you need changes immediately. [3]

### mongodb-order-lines (all): Pass, top score 0.7010

**Q:** Should order line items go in the same record as the order, or in a separate table?

*Note in test-questions.json:* Embed; relational wording ('record', 'table').

> Embed them in the same document as the order. Embedding is recommended when the related data is read together with the parent most of the time, when it belongs to the parent and has no life of its own (an order's line items are given as an example), and when the number of related items is small and bounded. [1] The example order in the document stores its items as an array inside the order, so reading it takes one lookup by `_id`, with no joins. [2] By contrast, in a relational database the same order would usually span three tables (orders, order_items, customers) and need joins to read back. [3]
>
> Referencing would make more sense if the number of items could grow without limit or if many parents shared the data. If every read needs a `$lookup`, the data probably should have been embedded. [1]
