### book-set-vs-project (all): Pass, top score 0.8281

**Q:** I want to add one field and keep all the others. Should I use $project?

*Note in test/questions.json:* No: use $set / $unset; $project only when the output shape is very different. Pages 26-31.

> No, use `$set` (or `$addFields`) instead. You should use $set & $unset stages when you need to retain most of the fields in the input records, and you want to add, modify or remove a minority subset of fields. [1]
>
> With `$project`, if you want to define one new field or revise one field, you will have to name all other fields in the projection to include. [2] Otherwise, you will lose those fields during the transformation. [3]
>
> `$set` also means no changes are required [4] when new fields later appear in your documents. The source's summary is: you should always look to use $set (or $addFields) and $unset for field inclusion and exclusion, rather than $project. The main exception is if you have an obvious requirement for a very different structure for result documents, where you only need to retain a small subset of the input fields. [5]
>
> Note that $set is actually just an alias for $addFields [6], and there is no behavioural difference. [1]

### book-filter-array (all): Pass, top score 0.6758

**Q:** How do I remove some elements from an array in each document without using $unwind and $group?

*Note in test/questions.json:* $filter inside $set. The chunk is mostly code (the suboptimal and optimal pipelines). Page 44.

> Use the `$filter` array operator inside a `$set` stage instead of an `$unwind`/`$match`/`$group` combination. The unwind approach introduces a blocking `$group` stage, which significantly increases memory consumption and execution time. Array operators avoid that blocking stage and are significantly more efficient, especially for large data sets. [1]
>
> Example from the book, keeping only products priced over 15.00:
>
> ```js
> var pipeline = [
>   {"$set": {
>     "products": {
>       "$filter": {
>         "input": "$products",
>         "as": "product",
>         "cond": {"$gt": ["$$product.price", NumberDecimal("15.00")]},
>       }
>     },
>   }},
> ];
> ```
>
> Unlike the unwind-based pipeline, this one will include "empty orders" for orders that contained only inexpensive items. If that's a problem, add a `$match` stage at the start of the pipeline with the same content as the `$match` in the unwind version. [1]
>
> If `$filter` isn't enough, there are alternatives. You can use `$reduce` with its "null array concatenation" trick when `$filter` does not suffice, for example when the ratio of input to output elements is many-to-few. Another option is to use `$map` with `$cond` to return an empty string for faulty elements, then wrap it in a `$filter` that removes elements with zero string length. [2]
