Claude Code for first-timers: setup and your first session

Claude Code is Anthropic's AI coding assistant. Unlike a chat window in a browser, it works directly in your project folder: it can read your files, search the code, run commands such as tests or git, and edit files, asking for your permission along the way. You talk to it in plain language, and it explains what it is about to do. It runs in a terminal, in a desktop app, and inside editors such as VS Code and JetBrains IDEs. This guide covers the terminal version on Windows and macOS, and the ideas carry over to the others.

Before you start, you need a Claude account with a paid plan (Pro or Max), or an Anthropic Console account with API credits, which bills per token instead of a monthly subscription. On Windows you also need Git for Windows, because Claude Code uses Git Bash to run shell commands. If you plan to install with npm, you need Node.js 18 or newer; the native installer does not need Node.js.

Installing on macOS or Linux: open a terminal and run the native installer with curl -fsSL https://claude.ai/install.sh | bash. Installing on Windows: open PowerShell and run irm https://claude.ai/install.ps1 | iex. The alternative on any system is npm install -g @anthropic-ai/claude-code. Do not use sudo with the npm command; if npm complains about permissions, fix the npm global folder instead. After installing, run claude --version to check that it worked, and claude doctor if something looks wrong. The native installation updates itself in the background.

Signing in: go to your project folder and type claude. The first time, it opens a browser window to log in with your Claude account, or you can choose to use an API key from the Console. Your login is stored, so you only do this once per machine. To switch accounts later, use /logout and /login inside a session.

Your first session: always start Claude Code from the root folder of the project you want to work on, because that folder is what it can see and change. A good first request is simply "explain what this project does and how it is organized". Claude reads the files it needs and answers. Then try a small, concrete task, such as "add a --verbose flag to the build script" or "the tests in utils fail, find out why". Describe what you want, not how to type it; you can refer to a specific file by typing @ followed by its name.

Permissions: by default Claude Code asks before it edits a file or runs a command. Each prompt lets you allow the action once, allow it for the rest of the session or always for this project, or refuse and tell Claude what to do instead. Read-only actions such as reading and searching files usually run without asking. Press Shift+Tab to cycle through the permission modes: normal mode asks before each change, accept-edits mode applies file edits without asking, and plan mode lets Claude read and propose a plan but not change anything until you approve it. Plan mode is a safe way to start a larger change.

Staying in control: press Esc to stop Claude in the middle of what it is doing, for example when it heads in the wrong direction; your conversation is kept and you can redirect it. Press Esc twice to go back to an earlier message and edit it. Claude Code also keeps checkpoints of the files it changed, so you can rewind a session's edits, but checkpoints are not a replacement for git: commit your work regularly, and ask Claude to commit for you if you like.

The CLAUDE.md file: run /init in a new project and Claude writes a CLAUDE.md file describing the project: how to build it, how to run the tests, the code style and the main folders. Claude Code reads this file at the start of every session, so it is where you put anything you would otherwise repeat, such as "use pnpm, not npm" or "never commit directly to main". Keep it short and specific. A CLAUDE.md in your home folder, at ~/.claude/CLAUDE.md, applies to all your projects, which suits personal preferences.

Useful slash commands: type / in a session to see them all. /help lists commands and shortcuts. /clear starts a fresh conversation, which is worth doing when you switch to an unrelated task, because a long history costs tokens and can distract Claude. /compact summarizes the conversation so far to free up room while keeping the important context. /model switches between Claude models. /resume picks up an earlier conversation, and claude --continue in the terminal reopens the most recent one. /cost or /usage shows what the session has used.

Settings: Claude Code reads settings from JSON files. The file ~/.claude/settings.json holds your personal defaults for every project. In a project, .claude/settings.json holds settings shared with your team and committed to git, and .claude/settings.local.json holds your own settings for that project, which git ignores. Settings include permission rules, such as always allowing npm test, and environment variables. You can also open /config inside a session to change common options without editing files.

Beyond the basics: claude -p "question" runs a single request without an interactive session and prints the answer, which is handy in scripts. Hooks run your own commands automatically at certain moments, for example a formatter after every file edit. MCP servers connect Claude Code to other tools and data, such as an issue tracker or a database. Skills and custom slash commands package instructions you use often, so you can run them by name.

Tips for good results: give context and a clear goal, and say how Claude can check its own work, for example "run the tests after the change". Break large tasks into steps and review each one. Read the diffs before you accept them, especially for code you will maintain. If Claude misunderstands, interrupt early instead of waiting for it to finish. And when something works well, put the lesson in CLAUDE.md so the next session starts with it.
